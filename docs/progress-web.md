### Review of Phase 2 (2026-11-10)

A code review of the phase, and a comparison with `a/core` and the contract, found these. All are fixed and each has a regression test.

| Found                                                 | Effect before the fix                                                                                |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Payroll line drawn vertically                         | The contract defines a horizontal reference line at the threshold amount                             |
| Saving a row closed editors open in other rows        | A half-typed value could be committed as an edit                                                     |
| Overlapping edits shared one callback                 | The first row stayed dimmed for good, and a refused edit was never reported                          |
| Edits could answer out of order                       | A slow response could overwrite a newer plan                                                         |
| A failed background refresh replaced the whole screen | The grid was lost over a passing error. It now keeps the data and says the figures may be old        |
| Do-not-contact changes could overwrite each other     | A client the owner had just protected could lose protection. Unmatched names also lost their warning |
| Editing the goal left the grid and runway stale       | `contactAllowed`, the gap and the deadline did not update                                            |
| Paid invoices left the grid                           | The list was open invoices only, so a deal vanished as it succeeded                                  |
| Rows in a cancelled plan said "Approved by you"       |                                                                                                      |
| An event could be overwritten by an older response    |                                                                                                      |
| `approval.decided` was ignored                        | "Needs you" could stay after an approval expired                                                     |
| Backups were invisible                                | The owner approved a plan without seeing that backups could go out                                   |
| Action and amount could disagree                      | The API rejects an early-payment discount for part of an invoice, and the mock did not               |
| The mock made deals before approval                   | The API creates them on approval, so draft rows looked different                                     |
| A client could open an owner screen by its address    |                                                                                                      |

### Known limits

- **Not run against the real API.** The first integration run is Phase 6, once A's routes exist.
- **Bundle size.** The grid chunk is about 2.8 MB (770 KB gzip) and the chart chunk about 1.1 MB (340 KB gzip). Both are lazy-loaded. The chart now registers only the modules it uses; doing the same for the grid is planned for Phase 6.
- **Mock data.** `src/mocks/world.ts` reproduces the CONTEXT.md scenario with the shared money helpers. It never changes payment state.
